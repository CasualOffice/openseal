Templates

A template saves what stays the same from one envelope to the next: documents, roles in routing order, the fields each role fills, and the email subject and message. When you use it, you only name the people.

Roles, not people

A template has roles such as "Employee" or "Company signer" instead of names and email addresses. Each role has a type (signer or carbon copy) and a routing order, and fields belong to roles. Using the template asks for one person per role.

Make one

  1. Open Templates and choose New template.
  2. Name it and add its documents. They are admitted and cleaned like any upload.
  3. Add the roles in routing order.
  4. Place fields for each role, as in the editor.
  5. Save. Edits later change the template only; envelopes already sent from it keep their own copies.

Use one

Choose Use next to a template, fill in a name and email for each role, adjust the message if you like, and send. You can also duplicate a template to start a variant, or delete one; envelopes made from it are not affected.

Through the API

Templates are a resource of their own: create one with roles, then add documents, roles and fields to it.

# A template with two roles
curl https://sign.example.com/api/v1/templates \
  -H "Authorization: Bearer $OPENSEAL_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: nda-template-1" \
  -d @template.json

# Its documents, roles and fields
POST /api/v1/templates/{id}/documents
POST /api/v1/templates/{id}/roles
POST /api/v1/templates/{id}/fields

The full list of template operations is in the API reference.
