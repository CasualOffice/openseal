Configuration reference

OpenSeal is configured entirely through environment variables. These tables are generated from each program's own documentation in the source, so they list exactly what the release reads.

How settings are read

  • Secrets have a file form. Every variable marked Secret can be given as NAME_FILE, the path of a file holding the value; prefer it, and the production profile uses nothing else. Setting both NAME and NAME_FILE is an error (CS-KEY-0005), and so is an empty or unreadable file.
  • Read once, at start. A change takes effect on the next restart. The exception is the database URL file, read again every OPENSEAL_SECRET_RELOAD_SECONDS so a credential can be rotated without a restart.
  • Refused, not guessed. A malformed or out-of-range value stops the program at start with one JSON start_failed line naming the setting and, where there is one, its error code.
  • Security settings are pinned. With OPENSEAL_CONFIG_MANIFEST (the production profile sets it), keyd and the worker refuse to start when a security setting differs from the recorded manifest (CS-KEY-0014). See recording the manifests.
  • Required means the program does not start without it; "With S3", "Outside development" and similar say when.

Server (casual-sign-server)

The API, the signing ceremony and the web app. Its subcommands (migrate, bootstrap, verify-evidence, mfa-reseal, blobs-export, blobs-import, healthcheck) read the same environment.

Worker (casual-sign-worker)

Runs every background job: email, reminders and expiry, sealing through keyd and the timestamp authorities, webhooks, daily anchoring and retention. casual-sign-worker config-manifest prints its manifest; casual-sign-worker healthcheck is its container health check.

Webhook signing secrets are not listed here: each subscription names its secret by reference, and the worker reads that reference as an environment variable NAME or NAME_FILE.

Key daemon (casual-sign-keyd)

Holds the seal key, one key per alias, and signs only for callers on its allow list over mutual TLS. casual-sign-keyd config-manifest prints its manifest; casual-sign-keyd verify-oplog PATH checks an operation log's chain.

Production profile (deploy/compose.production.yml)

The variables the profile itself reads when Compose renders it. It maps them onto the services' variables above and sets the rest (paths under /run/secrets/, listen addresses, the ops listener, the drain period). Compose refuses to start while a required one is unset, naming it.

Evaluation stack (docker-compose.yml)

The evaluation stack sets everything it needs itself. You may set OPENSEAL_HTTP_PORT (default 8080) and OPENSEAL_MAIL_PORT (default 8025) to move its ports, OPENSEAL_CLAMD_ADDR=clamav:3310 with --profile production to scan uploads, and OPENSEAL_IMAGE_PREFIX and OPENSEAL_VERSION to run published images. The optional settings it leaves unset (trusted proxies, GeoIP, identity providers, the SMS gateway, the model service, the webhook allow list) are yours to add.

Platform console

The separate operators' console (casual-sign-console) reads OPENSEAL_CONSOLE_DATABASE_URL and OPENSEAL_CONSOLE_MFA_KEY (secrets), OPENSEAL_CONSOLE_LISTEN, OPENSEAL_CONSOLE_ORIGIN, the OPENSEAL_CONSOLE_KEYD_* settings for its Keys page, and OPENSEAL_CONSOLE_TSA_ALLOW. They are documented with the console in docs/65.
