Deployment overview

OpenSeal runs on your own infrastructure as a handful of containers. Pick the guide for what you are doing: trying it on one machine, or running it for others.

OpenSeal is pre-release. v0.1.0 is for evaluation and for rehearsing a production deployment, not yet for production agreements. Nothing on these pages makes a deployment legally valid or compliant: that depends on your certificates, your processes and your counsel.

The services

OpenSeal is three programs of its own (the server, the worker and the key daemon) beside PostgreSQL and an S3-compatible object store. The same images run in both stacks; the production profile adds the hardening and a proxy in front of two server replicas.

Images

Every OpenSeal release publishes three images to GitHub Container Registry, ghcr.io/casualoffice/openseal-server, -worker and -keyd, for linux/amd64. Each digest is signed with keyless cosign by the release workflow and carries an SBOM and build provenance, so you can check exactly what you run before you run it: see Use the signed images. Third-party images (PostgreSQL, SeaweedFS, HAProxy, ClamAV, Mailpit) are pinned by digest in the Compose files. You can also build every image from source with docker compose build.

Platform console

casual-sign-console is a separate program for the people who run a deployment: health, organizations, approvals, keys and certificates, timestamp authorities, plans and usage limits, operators and the operator log. It is not yet a Compose service or a release image: build it with cargo build --release -p casual-sign-console, create the first operator with casual-sign-console bootstrap-operator, and run casual-sign-console serve, which listens on 127.0.0.1:8090 and refuses to start if its operator log does not verify. Its settings are in docs/65.

Kubernetes and high availability

A Helm chart and a multi-node reference are planned (VS-20). Until then, the production profile is the tested reference: the same images, environment variables and secret files carry over to any orchestrator.
