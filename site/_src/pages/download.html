Download and deploy

v0.0.1, the first pre-release, is published: the common send-and-sign case, end to end on one machine. It is for evaluation, not yet for production agreements. Everything below runs from a checkout of the repository; the demo and the verifier also run on this site, with nothing to install.

Release notes for v0.0.1{{icon:arrow-up-right:16}} View on GitHub{{icon:arrow-up-right:16}}

{{icon:triangle-alert:18}}Before you deploy: the pre-release limits

  • Not for production agreements yet. v0.0.1 is for evaluation.
  • The Compose stack generates its own certificate authority, software HSM and timestamp authority: its seals validate only against that development CA.
  • Release gates still ahead: an external security and cryptographic review, an accessibility audit, validation in Adobe Acrobat, and a counsel review. The ASVS self-assessment is written and its findings are being closed.
  • Backups: the encrypted, signed backup tool and the restore drill are built; the drill's run on CI is the last step before it counts.
  • No Helm chart or high-availability reference yet.

Each is tracked on the roadmap.

{{icon:container}}

The whole stack, with Docker Compose

Server, worker, key service, PostgreSQL, object storage, a mail catcher and a timestamp authority, on one machine.

git clone https://github.com/CasualOffice/openseal
cd openseal
docker compose up -d --build --wait

The release workflow also built the v0.0.1 server, worker and key-service images for GitHub Container Registry (ghcr.io/casualoffice/openseal-{server,worker,keyd}:0.0.1). Until those packages are public, build from the checkout as above.

Getting started covers the first administrator and a test envelope.

The web app, without a server

Demo mode keeps everything in the browser tab: send and sign a sample agreement; nothing is really sent or sealed. Open the demo on this site, or serve it from a checkout:

python3 -I tools/serve-webapp.py
# http://127.0.0.1:8130/app.html?mock=1
# demo@openseal.test / openseal-demo-1
{{icon:terminal}}

The openseal command line

Admit, fill, seal and verify PDFs headless, with the same engine the server runs. Needs Rust 1.96.

cargo build --release -p casual-sign-cli
target/release/openseal help
{{icon:shield-check}}

The offline verifier

The verify page with the engine compiled to WebAssembly. It runs on this site; to serve your own, build it with wasm-pack:

tools/build-webapp-wasm.sh
python3 -I tools/serve-webapp.py
# http://127.0.0.1:8130/verify.html

Deploying for real

The Compose stack is for evaluation and development: it makes its own keys and certificate authority. A production deployment needs a trusted document-signing certificate in an HSM, real timestamp authorities, a sending domain for email, and the rest of the checklist.
