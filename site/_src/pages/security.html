Security policy

If you find a weakness in OpenSeal, please tell us privately first, so it can be fixed before it is used against anyone.

Do not report in public

Do not open a public issue for a suspected vulnerability, a malicious PDF, a signature-forgery technique, or a real signed agreement.

How to report

Use GitHub private vulnerability reporting for the OpenSeal repository. Include:

  • the affected revision (a commit id);
  • the subsystem: PDF reader, sealing, verification, the signing ceremony, the API, or keyd;
  • the impact and a realistic attack path;
  • a minimal reproduction without personal data or real agreements.

We will acknowledge the report, assess it, coordinate a fix and an advisory, and credit you if you wish.

What we treat as critical

Signature and evidence issues come first:

  • a tampered document that still verifies;
  • a seal that verifies in one validator and fails in another;
  • an audit chain that can be altered without detection.

Supported versions

There is no release yet; OpenSeal is pre-alpha. Supported release lines will be listed here before the first preview.
