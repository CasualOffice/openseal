Getting started

Run the whole OpenSeal stack on one machine with Docker Compose, create the first administrator, and send yourself a document to sign. About ten minutes, most of it the first image build.

A development stack. It generates its own certificate authority, keeps the seal key in a software HSM and runs a local timestamp authority, so its seals validate only against that generated root, not in Adobe Acrobat. OpenSeal is pre-alpha: do not use it for real agreements yet.

What you need

  • Docker with Compose v2 (Docker Desktop, or Docker Engine with the compose plugin).
  • Git, and a few gigabytes of free disk for the images.
  • Ports 8080 and 8025 free on 127.0.0.1 (both can be moved, see below).

Start the stack

Clone the repository and start everything. --wait returns once every service reports healthy.

git clone https://github.com/CasualOffice/openseal
cd openseal
docker compose up -d --build --wait

On the first start a one-shot pki service writes a development CA, the TLS certificates between services, the seal key and certificate, a timestamp certificate, the API token key and random passwords into a secrets volume. Nothing secret is baked into an image.

Create the first administrator

An install starts empty. bootstrap creates the first account and its administrator, and prints their ids. Run it once; a second run with the same email is refused.

docker compose exec -e OPENSEAL_ADMIN_PASSWORD='a long passphrase' server \
    casual-sign-server bootstrap "Acme" admin@acme.example "Ada Admin"

Send yourself a document

  1. Open the web app at http://localhost:8080 and sign in as admin@acme.example with the passphrase you chose.
  2. Choose Start, then drop a PDF on the page.
  3. Add a signer with any email address, place a signature and a date field, and send. Sending your first envelope walks through each step.
  4. Open Mailpit at http://localhost:8025. Every email the stack sends lands there, including the signing invitation.
  5. Follow the link in the invitation, consent, and sign. When the last signer finishes, the worker seals the document and both the sealed PDF and its certificate of completion appear on the envelope.

Look around without a server

To see the web app without Docker, serve it in demo mode. Data lives only in the browser tab; nothing is sent or signed.

python3 -I tools/serve-webapp.py
# open http://127.0.0.1:8130/app.html?mock=1
# sign in as demo@openseal.test with the password openseal-demo-1

What is running

ServiceWhat it does
serverThe API, the signing ceremony and the web app, on port 8080
workerEmail through Mailpit, reminders and expiry, sealing through keyd and the timestamp authority, webhooks
keydThe key daemon over mutual TLS; the seal key in a SoftHSM token
postgresThe database; the application role is bound by row-level security
migrateOne-shot: applies every migration before the server starts
s3An S3-compatible blob store (SeaweedFS) for documents
mailpitCatches all email; web UI on port 8025
tsaA development RFC 3161 timestamp authority
pkiOne-shot, first start only: the development keys and certificates

Everyday commands

docker compose logs -f server worker   # what it is doing
docker compose down                    # stop, keep the data
docker compose down -v                 # stop and discard every volume (data, keys, mail)

Ports bind to 127.0.0.1 only. Set OPENSEAL_HTTP_PORT (default 8080) or OPENSEAL_MAIL_PORT (default 8025) to move them.

Check a sealed PDF yourself

Download the sealed PDF from the envelope, then fetch the stack's root certificate and check the seal with the browser verifier or any PAdES validator:

docker compose exec -T keyd cat /secrets/ca.pem > openseal-dev-root.pem

Open http://localhost:8080/verify.html, add openseal-dev-root.pem as a trusted certificate and drop the PDF. Verifying a document covers the offline and command-line options.
