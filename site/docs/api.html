API reference

OpenSeal API 1.0.0-alpha: 161 operations, rendered from api/openapi.yaml, the contract the server's route table is tested against.

Conventions

Envelope-centric REST API (docs/40). Errors are RFC 9457 problem details with a stable code (docs/20) and a request_id. Every POST accepts Idempotency-Key; replays within 24 hours return the first response. Envelopes carry an ETag ("v<version>"); edits of drafts and corrections need If-Match. Lists page with cursor and limit. Times are RFC 3339 UTC; ids are UUIDv7. Objects of another account answer exactly as missing ones: 404 CS-API-0002. The /s/{token} endpoints are the recipient ceremony, not public API (docs/40).

Authentication:

  • bearer: A personal API key (osk_…) or an access token from /api/v1/oauth/token (ES256 JWT, one hour).
  • session: Staff session from /api/v1/auth/login (named os_session only on a plain-HTTP development server); changing requests also send X-CSRF-Token. Every request body is application/json (else 415 CS-API-0007).

Webhooks, idempotency and errors are explained in Webhooks and the API design (docs/40).

POST/api/v1/auth/mfa/verify

Pass the session's second factor (ASVS-01)

With code, six digits from the user's authenticator (RFC 6238, 30-second steps, one step of drift either way); or with recovery_code, one of the ten codes shown at enrolment, which is spent (case, spaces and dashes do not matter). Each TOTP code is accepted once: a code for a step no later than the last accepted one is refused. 401 CS-AUTH-0012 for a wrong, replayed or spent code. Rate-limited per user as login is. Envelopes

GET/api/v1/envelopes

Envelopes, sorted and filtered, cursor-paginated (WEB-08)

The envelopes the caller may see (their own without view_all), never another account's, and never those removed from the lists (DELETE of an envelope that ended without completing) unless deleted=true asks for exactly those (the Deleted view, UXW-02). waiting_for=me is the Inbox (UXW-01): sent envelopes of this account, whoever sent them, in which the caller is, by their account email, a recipient whose turn it is and who acts through a link (not a copy, an in-person or an embedded signer); each item then has my_recipient_id. Every item has folder_id, the caller's own folder it is filed in, or null. Newest first by default. Keyset paging: a cursor belongs to the sort and order it was issued for (another is 422), and pages stay stable under inserts.

Needs scope envelopes:read
