Fixed

  • A saved recipient's type changed in the send editor is now kept on save: PATCH …/recipients/{r} takes type on a draft (UX-12).

Added

  • A redesigned web app from an audit against DocuSign and SignNow (UX-01, all seven packages UX-02 to UX-08): - a design system, with destructive actions in a colour distinct from the seal red, and the Inter font bundled; - a send editor with click-to-place fields, every field kind the signing page fills with its properties, recipient types and per-row options, contacts, a review step, starting from a template, a pages rail and a phone layout; - a reworked signing page; - Home, Agreements and the envelope page with clearer hierarchy, density and access to the evidence; - Templates, Reports (sample sizes, custom ranges) and an Admin section rail with webhooks; - an app shell that works on phones, with search on every screen, notifications, profile, account and help menus.
  • The signer's page names the sender and the expiry, and serves the electronic-records disclosure (GET /s/{token}/disclosure, UXW-34).
  • Organizations above workspaces (ORG-02, migration 0014): each existing account becomes a workspace in its own organization, with organization owners and an organization scope enforced in the database; server bootstrap makes the first organization; organization routes for owners and administrators (ORG-03), switching between workspaces (ORG-04), hash-chained admin audit logs per workspace and per organization with JSON and CSV export (ORG-05), and a first cut of the organization admin screens (ORG-06).
  • casual-sign-modeld, the separate process that hosts pretrained models (ADR-029): mutual TLS, a bounded wire protocol, an operation log and a hash-checked model bundle (ML-09); OCR of scanned pages (ML-02); page hashes and embeddings for template matching (ML-05). The worker's analysis jobs call it and the server serves analysis and suggestions (WEB-19); the Compose file does not yet put the worker on its network (ML-09).
  • GLiNER span extraction and personal-data detection in casual-sign-modeld, with fp16 exports matching the reference spans (ML-07, ML-08). Off by default; nothing a model says enters the evidence.
  • casual-sign-pii: personal-data recognisers that find structured identifiers by pattern plus validation (payment cards by Luhn, IBAN mod-97, US SSN, UK NI, Indian PAN and Aadhaar, and others), with a fuzz target (ML-08).
  • Inbox, each member's own folders, a Deleted view for envelopes and templates (templates can be restored), and server-side envelope filters and sorts (UXW-01 to UXW-03).
  • Bulk send from a template with a CSV list: per-row errors, a test of the list, sending in steps with progress, and cancel (POST /bulk-sends, UXW-04).
  • Template sharing with members, groups or the whole workspace; Shared with me and Favourites (UXW-06).
  • Groups and custom permission profiles, enforced on the server per request (UXW-07); the admin audit log screen (UXW-09); a webhooks screen that edits, pauses, tests and redelivers (UXW-10, UXW-31 to UXW-33).
  • Hosting an in-person signer (POST /envelopes/{id}/recipients/{r}/host, UXW-36).
  • Recipient authentication by SMS and voice one-time codes through an HTTPS gateway (VS-05) and by sign-in through an OpenID Connect provider the operator lists (RAUTH-01, ADR-033 Proposed).
  • The platform console casual-sign-console, a separate binary for operators with its own sign-in and mandatory TOTP: health, organizations with two-person suspend and resume, approvals, operators and a hash-chained operator log copied into each organization's log (CON-02 to CON-05, CON-16, CON-17); the Keys page over keyd's read-only admin interface (CON-06); timestamp authorities kept in the database and changed by two key custodians, which the worker seals with (CON-07, migration 0034). Not yet a Compose service.
  • Plans with versions, assignments and overrides (PLAN-02), metering of envelopes sent, seats, storage and workspaces (PLAN-03), and quota enforcement (PLAN-04).
  • An OWASP ASVS 4.0.3 self-assessment (docs/67, not a certification) and a licence inventory of every crate, vendored component and model (THIRD-PARTY.md, LEG-01).
  • Normalisation of extracted dates, durations and amounts in casual-sign-fields, with a fuzz target (ML-07).
  • Model manifest and hash-checking fetch script, an offline GLiNER export tool, and synthetic scanned-form fixtures (ML-01, ML-02, ML-05).

[0.0.1] - 2026-11-12 (pre-release)

The first pre-release of OpenSeal: the common send-and-sign case works end to end on one machine. Not for production agreements yet: the bundled stack uses a generated certificate authority, a software HSM and a development timestamp authority, so seals validate only against that CA.

What works

  • Upload a PDF, add signers in order or in parallel and carbon copies, place signature, initials, date, name, email, text and checkbox fields (with field detection), and send. Signers can also fill company, title, number, radio, dropdown, attachment and note fields that come from a template or a converted PDF form; the editor cannot yet place those (corrected 2026-11-12, DOC-007).
  • Signing on desktop and phone: access code, consent, guided Start/Next, draw, type or upload a signature, review, finish, decline, finish later, reassign when allowed; optional signer location (device or IP approximation).
  • Every completed envelope is sealed as PAdES (B-T by default) and verified before it completes; a certificate of completion with the hash-chained audit trail embedded. Outputs are checked by pyHanko and EU DSS in CI.
  • Agreements, envelope detail with audit trail, Correct, resend, void, downloads in progress and when complete, templates, admin (users, invitations, API clients), reports, and Verify in the browser.
  • REST API (/api/v1, OpenAPI document) with API keys and OAuth client credentials; signed webhooks.
  • Engine: bounded PDF reader (417 of 422 real-world PDFs admitted, the rest refused with codes), incremental writer, print-to-new for certified PDFs, dynamic XFA forms laid out to static pages, 24 h of fuzzing per target.
  • One-command deployment with Docker Compose; images on GitHub Container Registry.

Not yet

SSO (OIDC, SAML), WebAuthn, SMS authentication, bulk send, payments, B-LTA renewal jobs, production deployment (Helm, high availability, backups), and the slices after Release 1 on the roadmap.

Security

Report vulnerabilities as described in SECURITY.md. This is pre-release software; do not use it for agreements you need to rely on.
