# 08 — ADR register

ADR ids here are this repository's own; the sisters' are always cited as "OpenCalc's ADR-n" or "OpenPresent's ADR-n".
ADR-001 to ADR-009 are Accepted on the owner's "proceed" of 2026-11-10 (instruction 6); ADR-005 and ADR-006 still have their spikes (`SPK-01`, `SPK-02`) confirm the library choice, and change only by a superseding ADR. **Proposed unless marked.** Status moves to Accepted when the owner agrees, or when the spike named in the row confirms
it.

**Write an ADR when a decision touches:** public API; a crate boundary or the DAG; a persisted or wire format; the
envelope state machine; the audit event schema; cryptographic algorithms, libraries or key custody; what enters the
WASM bundle; a new dependency in the engine; a legal or evidence property.

| ADR-029 | **The ML model seam (`ML-01`) and how models are hosted.** Pretrained models only, no training (owner instructions 27, 28, 30). They run in a new server-layer process, `casual-sign-modeld` (`ML-09`), never in `crates/`; the engine stays pure and wasm32. modeld is built like keyd: TLS 1.3 mutual TLS on `rustls` with `aws-lc-rs`, length-prefixed bounded binary frames, and an op log of counts and ids only. **Every inference dependency is optional behind modeld's `server` feature**, which only its binary requires; the worker links modeld with `default-features = false` and gets the wire format and client only, so the secret-holding worker never links the inference stack (`SEC-I14`). modeld holds no database, SMTP, webhook or keyd credentials and runs on an internal network with no egress. The worker calls it from new advisory job kinds, `analyze_document` and `fingerprint_template`, whose idempotency keys carry the account and document id (`SEC-I06`). Those jobs are not workflow effects and touch no envelope state, so turning the features off enqueues nothing. Inference uses ONNX Runtime 1.28.x (MIT, bundling Eigen MPL-2.0 and Boost BSL-1.0, which owner instruction 32 allows inside that unmodified binary in the modeld image only, shipped with its ThirdPartyNotices), pinned by SHA-256, through `ort =2.0.0-rc.13` (MIT OR Apache-2.0) with `default-features = false` and `load-dynamic`, CPU only, fixed thread count. That rc is the exact version required by `oar-ocr =0.10.2` (Apache-2.0), which supplies the PaddleOCR pipeline with `default-features = false` (its defaults download ONNX Runtime at build) and `auto-download` off. GLiNER span decoding (extraction and personal data) is our own code on the same `ort`, not `gline-rs`, which requires `=rc.9`. `tokenizers =0.23.2` runs with `default-features = false`; Oniguruma (C) still comes in through `oar-ocr-core` and is fuzzed. Third-party `tracing` events below WARN from `oar_ocr*`, `ort`, `hayro*` and `tokenizers` are dropped whatever `RUST_LOG` says, because `oar-ocr` logs recognised text at debug (`SEC-I05`). Pages are rasterised by `hayro` 0.8.0 (Apache-2.0 OR MIT; the crate forbids `unsafe`, its dependencies do not) in a per-document child process of modeld that can be killed alone, with pixel, decoded-data, address-space and time caps; the slot count is derived from memory. ADR-007 is unchanged: the engine still never rasterises. Personal data is found first by deterministic recognisers in a new pure engine crate `casual-sign-pii` (engine dependencies `phonenumber` 0.3.10, `email_address` 0.2.9, `iban_validate` 5.0.1; created only if it builds for wasm32, else a worker module), then optionally by GLiNER-PII in modeld. Models: PP-OCRv6 small (det, rec) with operator-chosen PP-OCRv5 script packs; multilingual-e5-small (fp32, CPU-portable) plus dHash/pHash for template matching; GLiNER `gliner_multi-v2.1` (int8 export of our own) for extraction; knowledgator `gliner-pii-base-v1.0` (English only) as the optional personal-data layer. Weights are pinned by SHA-256 and revision in a committed manifest, each with a licence on `deny.toml`'s allow list, checked by the fetch script only (no new CI gate). They are fetched at image build, never at run time; exports from pickle load only with `weights_only=True` from a hash-pinned file; modeld refuses to start on a mismatch and never loads pickle. Each feature is off by default and enabled per workspace when the plan entitles it (`PLAN-01`). Outputs are suggestions a person accepts. They never enter the sealed document, the audit chain or the evidence, and each records model id, weight hash and runtime version. **Rejected:** `ort` inside the worker (a C++ runtime and hostile rasters next to every secret, OCR starving sealing and email jobs, no way to stop a hung run without killing the worker); a Python model service with Presidio, spaCy and onnxruntime (outside cargo-deny, a second toolchain, a large image; tldextract fetches the Public Suffix List over the network by default); PaddlePaddle at run time (heavy framework, downloads from model hubs; used offline only to export script packs); `tract-onnx` as the main runtime (slower, patchy int8; kept as a fallback); `fastembed` (downloads from the HF hub at run time); PDFium as the default rasteriser (C++ with a CVE history; kept as a sandboxed fallback under `PDF-REN-01`); the AVX-512-only int8 e5 file; openai/privacy-filter (over the memory cap). **Recorded fallback:** a Python Presidio sidecar under the same mTLS and no-egress rules, only if the Rust personal-data recognisers miss ML-08's detection-rate gate. **Open:** reliance on weight licences where training data is non-commercial or undisclosed (D13, docs/09 §8), and `ML-06` (docs/33 §5.8) | Accepted (owner, 2026-11-12, instruction 30), with the adversarial review's defects fixed (docs/33 §16) | [33](33-ML-MODELS.md) |
