# 21 — Parser and input limits

Every limit the code will hold, its default, its code, and whether a hostile fixture proves it. **Built and tested:** every PDF limit (`casual-sign-pdf`), the cryptographic limits (`casual-sign-crypto`,
`casual-sign-verify`) and, under Fields and envelopes, field id, data label, rectangle, regex, numbers, value length,
options, formula bounds, anchors, tags and text extraction. **Proposed, not built yet:** envelope total, recipients,
fields per envelope, subject and message, custom fields, attachment size and bulk sends (images and drawn points are built, stage 1E). Every PDF
limit with a code has a hostile fixture or a stated reason for none has a hostile fixture, generated by
`fixtures/tools/generate.py` and listed in `fixtures/hostile/manifest.tsv` with its expected code (`F-005`). Each default becomes a host-overridable value in `casual-sign-pdf::Limits` or the server's
configuration; the defaults are chosen to admit every corpus document with headroom, and are re-measured at the
Phase 1 gate.

## XFA (`casual-sign-xfa`, `XFA-01`)

Dynamic XFA forms are laid out into static pages (docs/30 §3). The packets come out of the PDF through the reader's own
limits (stream size, decode ratio and budget); these bound the XML and the layout. Each has a hostile fixture, a
dynamic-only form the reader refuses with `CS-PDF-0012` whose packets `casual-sign-xfa` refuses with the code below
(`crates/casual-sign-xfa/tests/hostile.rs`). Corpus maxima, measured over the 40 corpus files with XFA: XDP 14.1 MB
(`opm-sf86`), element depth 16, container nesting 8.

## ML (`casual-sign-modeld`, the worker's ML jobs; designed, ADR-029)

Designed in [33](33-ML-MODELS.md) §4. Built so far: span normalisation (`casual-sign-fields::normalize`, `ML-07`), the
deterministic personal-data recognisers (`casual-sign-pii`, `ML-08`), whose rows name their tests, and the `casual-sign-modeld`
skeleton, which enforces the 64 MiB frame cap, the 4 MiB cap on requests other than DOC_OPEN and HASH, the id bounds and
the pre-admission bound, and the rasteriser (`ML-02`, `src/raster.rs`), which enforces the raster, decoded-image,
nesting, time, kill and address-space rows below in its child process. Their hostile fixtures are the `ml_*` files of
`fixtures/hostile/ml/` (`generate.py --ml`, own manifest), asserted by `server/casual-sign-modeld/tests/raster.rs`.
